## Interview Talking Points

### For "Tell me about a challenging bug you fixed:"
"I debugged a complex integration issue where the frontend couldn't connect to the backend API. After systematic investigation, I identified three separate problems: CORS configuration issues, environment variable priority conflicts that caused production URLs to be used instead of local emulators, and API URL path construction bugs where the function name and route paths combined incorrectly. I fixed each issue sequentially, ultimately achieving 100% API endpoint availability. This taught me the importance of understanding how different environments handle configuration differently."

### For "How did you optimize database performance:"
"I optimized the MongoDB schema by implementing indexed queries on userId fields for user data isolation. This allowed efficient filtering of user-specific transactions without full collection scans. I also implemented date range queries with proper indexing, enabling fast time-period filtering. In testing with 1000+ transactions, I achieved <100ms response times for monthly aggregations and 2,000+ transactions/second throughput for CRUD operations."

### For "Tell me about your deployment process:"
"I set up a CI/CD pipeline using GitHub Actions that automatically builds and deploys the application on every push to the main branch. The pipeline runs linting checks, builds the React frontend with production environment variables from GitHub Secrets, and deploys to Firebase Hosting. This eliminates manual deployment steps and ensures consistent, tested deployments. All sensitive credentials are managed through GitHub Secrets, keeping the codebase secure."

**Be Specific About:**
- "In testing with 1000+ records..." (when mentioning performance)
- "Verified in local development environment..." (for metrics)
- "Designed to support..." (for scalability claims)

**Don't Claim:**
- Production user counts (unless you have real users)
- Revenue or business metrics
- Traffic numbers you can't verify
